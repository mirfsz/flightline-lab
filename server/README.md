# Local research service and bounded public archive pack

From the project root, using Python 3.11 or newer:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r server/requirements-dev.txt
.venv/bin/python -m uvicorn server.main:app --host 127.0.0.1 --port 8000
```

Install `ffmpeg` separately (`brew install ffmpeg` on macOS) to accept compressed audio and video. If it is missing, mono/stereo 16-bit PCM WAV at 8–96 kHz remains supported. Numpy and SciPy are required; missing scientific packages cause a clear Python import/install error at startup. Run `.venv/bin/python -m pytest tests -q` for verification. Interactive API documentation is at http://127.0.0.1:8000/docs.

`POST /api/fixtures/analyze` synthesizes a deterministic 45-second tone passage and compares its ridge to a fixed 10 km imaginary grid. `GET /api/fixtures/demo.wav` downloads the corresponding reproducible fixture. This fixture uses no recordings of people, geographic coordinates, real flights, online APIs, or identity data.

`GET /api/archive/coverage` lists the installed immutable regional/date packs and their observation span, coarse bounds, provenance, attribution, canonical content hash, and demo request metadata. The included Singapore pack contains **three adsb.lol public observations across 24.007 seconds on 2026-11-18**, labelled Anonymous passage A. This is incomplete traffic coverage within a short public observation span, not a full-day Singapore archive. The pack retains no aircraft identity, callsign, receiver metadata or private recording. Capture times are API observation times, not independently verified aircraft transmission times. Requests use local installed data and make no network calls.

`POST /api/demo/analyze` generates a 20-second synthetic constant-tone signal from interpolation between those real public observations and compares it to coarse Singapore cells. `GET /api/demo/demo.wav` downloads that generated WAV. The WAV is **not a real aircraft recording**. Its correct metadata is `recording_time=2026-11-18T15:00:20.001Z` (23:00:20.001 in Singapore), `search_region=Singapore`, and `time_uncertainty_minutes=0`; these values are also returned by the coverage endpoint. Download headers include `X-Recording-Time`, `X-Search-Region`, and `X-Audio-Is-Synthetic`. The arbitrary simulator receiver input stays internal and is not an inferred receiver location.

`POST /api/analyze` accepts multipart `media`, timezone-aware ISO `recording_time`, `time_uncertainty_minutes` (0–1440), `search_region` (1–200 characters), and `consent_confirmed=true`. Use only recordings you own or have permission to process. Region aliases are explicit: the installed pack accepts `Singapore` or `SG`, with case and surrounding whitespace ignored. If the requested region and time uncertainty window overlap this pack, uploaded audio follows the public observed-trajectory comparison path. For example, upload the public demo WAV using its correct metadata to exercise that path. Unsupported regions/dates return HTTP 200, `decision=inconclusive`, no cells/map, and a plain structured `archive_match` with `region_unavailable` or `time_unavailable`. Valid archive overlap is `installed_overlap`, which alone never implies a compatible audio fit.

The model evaluates fixed samples inside geographic cells, linearly interpolates aircraft positions and altitude between observations, and computes sound propagation delay and Doppler. It tests only complete recording windows supported by the observed span, without path extrapolation. A bounded two-second clock grid respects the supplied uncertainty. The emitted pitch is fitted as a nuisance parameter. Cells with at least one sampled hypothesis below the illustrative 5 Hz RMS error threshold are returned as **compatible coarse cells**. This uncalibrated threshold has not been validated against real recordings or competing aircraft. A short span and a simple tone can produce multiple compatible cells; compatibility does not locate a microphone or identify an aircraft. Fixed source tone, stationary receiver, constant sound speed, sparse observations and clock uncertainty severely limit inference.

The response contains `decision`, `reason_codes`, `coarse_cells` (cell ID, label, and qualitative fit label), `evidence_summary`, a bounded `spectrogram.values` row matrix, and `limitations`. `evidence_kind` distinguishes `synthetic_fixture`, `public_observation`, and `no_archive`; `archive_match` gives the coverage result and attribution. `synthetic_only` describes the evidence source, while `audio_is_synthetic=true` identifies explicit generator endpoints. Audio provenance is unknown (`null`) for uploads. No aircraft identity or exact receiver position is exposed. Grid cells are always at least 10 km across; labels and scores are not calibrated probabilities.

Supported fixture responses contain `evidence_map`, tagged `synthetic_only: true` and `coordinate_frame: "fictional local kilometres"`. Each of its three ranked candidates describes the same invented passage against a different receiver hypothesis: a synthetic label, 10 km cell bounds, nine track points with emission times, a disk enclosing the entire receiver cell, Doppler RMSE in Hz, and closest-approach emission/arrival timing with propagation delay and tone-transition residual. The transition is detected against the fitted emitted pitch, so the residual is a diagnostic of the Doppler fit rather than independent evidence. The disk is illustrative. Local x/y values are fictional distances, never latitude/longitude.

Supported public responses instead have `evidence_map.coordinate_frame="geographic coarse cells"`, `synthetic_only=false`, `passage_label`, three anonymous `track_points` (`latitude`, `longitude`, `observed_at`; aircraft positions rounded to 0.001 degrees), and `candidates` containing a label, cell ID, fit error and coarse `cell_bounds` (`south`, `west`, `north`, `east`). These bounds describe 0.1-degree Singapore cells over 11 km across. Public maps contain **no microphone center, optimized receiver point, exact closest-approach marker or fictional x/y frame**. All inconclusive maps are `null`. The synthetic fixture remains isolated under `/api/fixtures/*`; uploading its 45-second WAV cannot fit the 24-second public observation span.

Pack format, validation and ODbL redistribution details are in [packs/README.md](packs/README.md). Contains information from [adsb.lol](https://www.adsb.lol/), made available under the [Open Database License (ODbL)](https://opendatacommons.org/licenses/odbl/1-0/).

Uploads are capped at 25 MB before multipart parsing (plus a small bounded form overhead). Each file is copied in bounded chunks into a private temporary directory using a fixed generated basename, never its submitted filename. ffmpeg runs without a shell, with one decode/encode thread, no network input protocols, a 30-second timeout, and at most 91 seconds of mono 8 kHz decoded output. The extra second lets the service reject recordings exceeding the 90-second duration limit. Requests are gated before multipart parsing and processed one at a time; concurrent analysis gets 429. Browser requests from non-local origins are rejected before decoding. WAV fallback validates rate, channels, frame count, and sample width before reading. These are practical local POC limits, not authentication or an OS sandbox: only process trusted, consented input locally, keep ffmpeg updated, and bind to loopback.

Temporary upload and decoded files are removed on success and handled failure, and multipart handles are closed. No recording, result, or metadata database exists. `DELETE /api/recordings` confirms no retained recordings; it does not cancel an in-flight request. A hard process kill or machine failure can leave an OS temporary directory, which should be removed using normal OS temporary-file maintenance. `GET /api/health` reports decoding capability and configured limits.
